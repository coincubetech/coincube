# Imported Bitcoin signing compatibility (R15a)

This is the bounded contract for full Bitcoin imports in #768. It does not enroll keys, persist secrets, or turn on a new signing route. The test-only signer proof in `coincube-gui/src/services/imported_signer.rs` accepts a transient synthetic imported root key, checks its **full derived account xpub and origin path** against the admitted descriptor, signs a cloned daemon draft through `bitcoin 0.32.8` `Psbt::sign<GetKey>`, and returns it only after `verify_imported_signatures` checks the original PSBT. A failed or partially successful upstream sign never returns the mutated clone. The Cube master key is never substituted for an imported key. R15b must specify and verify the production lifetime and zeroization of imported mnemonic, passphrase, seed and derived private keys before enabling this route.

| `pkh` | Synthetic sign/finalize proof | Policy accepted; device-specific restrictions apply | No generic import route |
| `wpkh` | Synthetic sign/finalize proof | Policy accepted; device-specific restrictions apply | No generic import route |

| `wsh(sortedmulti)` | Two independent roots satisfy 2-of-3 synthetic proof | Policy accepted; device-specific restrictions apply | No generic import route; phone also rejects `sortedmulti` |

`ImportedWalletDescriptor::from_descriptors` admits only the complete origin-tagged, ranged receive/change pair (`coincube-core/src/wallet_descriptor.rs:104`). Hardware `imported_policy` converts it to one `<0;1>` device policy (`coincube-gui/src/split_hardware/policy.rs:153-169`), and the existing imported panel calls `SigningSession::register` and `sign` before `verify_imported_signatures` and daemon update (`coincube-gui/src/app/state/imported_bitcoin.rs:1667-1750`). The hardware tests in `coincube-gui/src/split_hardware/sign/tests.rs` use mock devices, so this report makes no physical-device claim. BitBox02 explicitly refuses `pkh` (`sign.rs:408`); the device matrix and pairing state still govern any actual signer.

The current LAN binding and response verifier parse `CoincubeDescriptor` (`coincube-gui/src/phone_signer/pairing_store.rs:121`, `signatures.rs:70`), which requires a multipath VAULT policy (`coincube-core/src/descriptors/mod.rs:114-139`) rather than any of the five imported shapes. The verifier also requires `witness_script` for an ECDSA delta (`signatures.rs:164`), so simply accepting a generic `wpkh` descriptor would still fail. The Connect desktop signing flow is likewise VAULT-oriented. Read-only inspection of sibling `keychain-app` at `a4f095515a6da1bdd839b6817cabc4ea6afb53d5` found a BDK-based signer (`lib/blocs/signing/bloc/signing_bloc.dart:2852-2882`) that can parse generic policies in principle, but its `_isSupportedCoincubeDescriptor` expressly rejects `sortedmulti` (lines 3368-3369). No end-to-end generic Keychain import binding has been proven; a phone key must match the exact imported account xpub and origin. Supporting these policies requires a separate, reviewed compatibility contract, and `sortedmulti` requires a Keychain change. There was no phone, network, or live transaction test.

The existing Recovery Kit has v1 `SeedBlob` for the Cube mnemonic and v2 `ImportedDescriptorBlob` for public imported wallet metadata. Neither contains independent local imported secrets. The test-only v3 payload proof in `imported_signer/tests.rs` round-trips synthetic mnemonic/passphrase/path provenance through the existing authenticated `recovery::encrypt`/`decrypt` envelope and rejects unknown payload version, wrong Cube, and wrong wallet identity. The production R15c writer/reader must put independently imported local secret(s) inside that envelope, bind the Cube UUID, network and full imported wallet identity, rederive every stored key against the descriptor on restore, and preserve the v1/v2 readers. Hardware and phone keys remain external and must be reported as unavailable after a clean-device restore until reconnected. A v2 metadata-only Kit must never be labeled a complete local-key backup. This proof does not establish production backup/restore completion or server-confirmed upload.

Tests in the signer proof cover wrong root and path, foreign outpoint, changed recipient/change amounts and fee, changed authenticated previous output, altered sighash, and an incomplete previous transaction. The core `imported_spend` finalizer also checks every partial signature, authenticated prevouts, actual script replay and fee range. The GUI adapter must retain the original draft and wallet identity for every asynchronous return; its current panel generation check is the model for cancellation/lock handling.
