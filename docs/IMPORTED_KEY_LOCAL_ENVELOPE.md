# Imported Bitcoin key authority and local envelope

This internal foundation admits one independently supplied English BIP39 key to one exact imported Bitcoin descriptor account. It checks the master fingerprint, full origin path and derived account xpub in both receive and change branches. The resulting opaque key handle signs only ordinary `/0/index` or `/1/index` children of that account. It is not a Cube/Vault seed, and this foundation does not yet wire import, unlock, Send, or Recovery Kit UI.

The local imported-key record has its own marker, `CC_IMPORTED_KEY!`, and never enters the Cube seed-file reader or filename discovery. The wire length is fixed at **1092 bytes**: marker 16, header 8, salt 16, nonce 12, padded plaintext 1024, and GCM tag 16. The header is `[version, Argon2id ID, memory KiB u32 BE, passes, lanes]`; version 1 is explicit PIN-only on a platform without an OS keystore, version 2 requires the supplied device secret. A missing or locked keystore is an error, never a reason to write version 1. Production parameters retain the seed-file floor of 256 MiB, 3 passes, 4 lanes. Reader limits bound header work before Argon2 allocation. Imported device-bound keys use a separate HKDF domain from seed V3.

The 1024-byte plaintext uses an eight-byte frame magic, two `u16` big-endian byte lengths, raw UTF-8 mnemonic and raw UTF-8 passphrase, then zero padding. The English mnemonic limit is **256 UTF-8 bytes**; the optional passphrase limit is **256 raw UTF-8 bytes**. Both are product/UI limits, not BIP39 limits. No input is truncated. A 24-word English phrase can be at most 215 bytes, so the 256-byte limit covers it; the binary frame's maximum used capacity is 12 + 256 + 256 = 524 bytes, leaving 500 bytes of padding. The exact typed passphrase is retained in the sealed payload; BIP39 NFKD normalization occurs only during key derivation. Later import and restore UI must show and enforce these same byte limits, including Unicode cases whose normalized representation grows.

GCM authenticates the marker and header and a length-prefixed context: Cube ID, chain, import operation UUID, full receive/change wallet identity, admitted canonical full-policy hash, master fingerprint, full account origin, account xpub, key-record UUID and fresh admission-revision UUID. The full-policy hash is an input from the already admitted canonical D1 policy bytes. Later persistence code must carry that exact committed value rather than independently serializing a descriptor. Swapping a record or replaying an older revision must fail authentication. The key file itself is only a codec here; durable admission, atomic persistence, unlock orchestration and owner recovery are subsequent slices.

Cube seed V1/V2/V3 formats, their 256-byte padding and legacy readers remain unchanged. The Recovery Kit's password KDF is not used for a PIN-protected local key.
