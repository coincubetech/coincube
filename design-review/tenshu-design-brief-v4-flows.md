## Corrections from Robert (2026-10-22, after reviewing the V4 row)

### Split = clone the Vault to Bitcoin Blake2b (not a coin selector)
- The purpose: take an existing Bitcoin Vault and create a MATCHING Bitcoin Blake2b Vault (same keys, same policy) in a NEW Bitcoin Blake2b Cube. That is what lets the user spend the Blake2b side of their coins, because spending there needs the same keys as the Bitcoin Vault. So the action clones the Bitcoin Cube and Vault into a new Cube + Vault on Bitcoin Blake2b.
- Gate: the feature is shown ONLY when Bitcoin Blake2b beta access is enabled for the account. Never tell the user to enable it; when it is not enabled the option simply does not appear (give the artboard a lever `btcb2Beta` boolean, default true, to review both states).
- Placement: it is an option that appears when the user selects the Vault as "From" in the Transfer flow ("Create a Bitcoin Blake2b copy of this Vault…" as a row/action under the selected Vault), not a separate selector below Continue.
- Flow (state `split`): 1) Explain: "Creates a new Bitcoin Blake2b Cube with a Vault that mirrors this one: same keys, same 2-of-3 synthetic policy. Spending Blake2b-side coins needs those keys." Show the source Vault identity and policy, and the signers it will mirror. 2) New Cube: name (default "Family savings · Blake2b"), network fixed and shown as Bitcoin Blake2b mainnet with the gold mark, PIN/passkey for the new Cube (every Cube has its own), note that the seed is reused. 3) Creating: step list (Checking Bitcoin Blake2b admission → Creating Cube → Creating Vault with mirrored policy → Registering signers). 4) Done: "Blake workspace copy created" with "Open the new Cube" (link to the Launcher) and "Split coins (next step)". The coin split itself is the EXISTING multi-step flow in the app (labels from source: "Before fork · both chains", "Bitcoin-only", "BTCB2-only", "Build step 1", "Build step 2", confirmations, "Abandon split"); summarize it in three lines as what comes next; do not redesign it here. Keep "Mechanics subject to source validation" only on the creation step list.

### Send: no rail until there is a destination
- The You send / They receive blocks show the asset coin and name only; the rail badge on the coin and the rail tag (SPARK / LIGHTNING / ON-CHAIN …) appear only after a destination has been entered and detected. Before that the "They receive" block reads "Add a destination" in muted text with no tag.

- Spark receive "From another network" (and the matching Send "Stablecoin (cross-chain)" kind) list the stablecoin rails as in the current app: USDt on Ethereum, Tron, Binance, Solana and Liquid; USDC on Ethereum and Solana. Each row: asset coin (teal USDt "T" mark; blue USDC "$" mark) with a small network badge at the bottom-right (Ethereum, Tron, Binance, Solana, Liquid as simple drawn glyphs; no third-party logos), asset name, and the rail tag.
